# OneSchedule 项目代码审查与整理

## 一、范围与审查流程

1. 先确认用户授权范围、现有改动和行为契约。讨论阶段只读；实施阶段以已确认的需求为准，不扩大为无关重写。全面审查时覆盖整个项目；专项审查沿受影响的数据流、调用方和生命周期展开。
2. 将发现分为**正确性必需修复**、**可靠性与维护性建议**、**可选风格调整**。对真实缺陷做最小必要修正；保持未要求改变的功能、外部接口和预期行为，不将 MVVM 风格偏好当成功能缺陷。
3. 检查代码、调用方、测试、示例和文档的冲突与重复。移除本次变更淘汰的分支，不并行维护两套周期或 JSON 规则；同步相关文档。
4. 对已合理的实现不作无意义重构。重大功能或架构迁移先提出方案，已确认的变更直接实施。

## 二、架构、职责与状态

检查模块划分、职责分配和函数设计：模块内部高内聚，模块之间低耦合，避免职责混乱和不必要的依赖。按项目现有规模划分，不机械增加层次。

| 部分 | 审查要点 |
| --- | --- |
| Model（Models/）与领域规则 | 日程结构、历法、周期与数字日期不依赖具体视图、控件或 ViewModel；显示文字与存储数值分开。 |
| View（Views/、Controls/） | 负责展示和界面交互；焦点、滚动、动画、布局及控件特有行为可以保留在 code-behind。可独立运行的业务规则、数据访问和持久化放入相应业务或数据层。 |
| ViewModel | 在确有界面状态、命令或用例协调收益时引入，通过属性通知、绑定和命令连接 View；不直接依赖具体 Window/控件或通过查找控件读取业务状态，不承担文件解析、存储或播放引擎等底层实现。 |
| Services/、Algorithm/ | 集中持久化、实际发生日期、农历转换、提醒和系统能力；窗口可通过具体服务直接协调，Model 不反向依赖窗口。 |
| App 入口 | 负责启动与必要对象协调，避免循环依赖。 |

- 检查状态来源、属性及集合通知、命令可执行状态是否正确更新，防止显示与实际状态不一致。
- 检查异步结果更新、UI 线程访问、事件订阅与释放，以及定时器、声音和托盘图标的生命周期。
- 不以 code-behind 为空、类名或目录形式作为合格标准；不强制引入 MVVM 框架、DI 容器、消息总线、通用仓储或插件层。

## 三、代码质量与项目清理

- 检查程序逻辑、命名、异常处理、可读性及函数设计；优先简单、直接、清晰的实现，消除不必要的复杂性、冗余和重复。
- 允许少量简单重复，合理复用复杂重复逻辑；仅在降低整体复杂度、提高可维护性时引入抽象，不追求高级语法，不以减少行数、类、函数或模块数量为目标。
- 只清理确认无用的文件及本次产生的临时内容、构建垃圾，必要时完善 .gitignore。保护资源、配置、现有日程、备份及原有未提交改动；不得把读取失败当成空列表覆盖保存。

## 四、OneSchedule 行为契约

### 4.1 运行环境与发布

- 主程序和检查仅面向 net10.0-windows；Windows x64 框架依赖单 EXE 要求 .NET 10 Windows Desktop Runtime，不保留 .NET 8 目标或跨主版本回退。
- 发布/测试路径及当前说明保持一致，历史记录保留原样。

### 4.2 历法、周期与提醒

- 周期为无/日/周/月/年；repeatCount 包含起始日，1～999，none 为1；年默认100，日/周/月默认2。所选日期是起始日，之前不发生；日/周间隔1/7个实际日。
- 月/年按所选历法匹配；不存在日期跳过且不消耗次数，禁止改为月末。阴历月重复包含普通月与闰月；年重复保持同月、同日、同闰月属性。
- 阴历以数字年/月/日和独立闰月标志存储，不能构造为阳历 DateTime。显示年二〇二六、月正…十/冬/腊及闰月、日初十/廿一；年/月/日单位在下拉框外。
- 日历事项标记、当天列表和提醒共用实际发生规则；重复事件只存一条规则，编辑/删除作用于整条规则。
- 提醒按每次发生的阳历日期去重；跨午夜提前提醒记录目标发生日期。覆盖同日多事件、重启、保存失败及规则改变后的记录处理。
- 同一天的三角形按事件时间选取尚未提醒的下一项，同一时间保持原有顺序；按该日期的提醒记录判断，不能用其它发生日期的记录排除当前日期。
- 提醒记录保存成功后立即更新标记，保存失败不得误前进；今天已错过补发窗口的项目让位给后续事件。未来/历史日期保留日程标识；全部提醒或全部过时后保留末项颜色。有时间的待办优先于无时间事项；更新颜色不删除事件或精简悬停内容，不新增持久化完成字段。

### 4.3 JSON 与保存保护

- 标准 UTF-8 JSON，schemaVersion=2，备注字段写为 note；旧 location 一律拒绝，不自动转换或覆盖。对照 [JSON 契约](../../data-format.md) 检查模型、解析/序列化、示例、校验、测试和 README，不另写相互矛盾的格式。
- 应用只直接接受版本2；版本1仅通过明确授权的开发升级工具转换，保留原字节备份，禁止静默迁移。旧/损坏/未知版本文件明确拒绝并阻止覆盖，保留原文件与备份。
- 多文件事件 ID 按 GUID 值判等，跨文件与单文件校验一致；仅写回所属文件。保存失败只清理本次创建的临时文件，禁止覆盖或删除已有临时内容。

### 4.4 界面、托盘与生命周期

- 保持紧凑 WPF DIP 布局及 PerMonitorV2；检查传统阴历文字、闰月、验证提示和提醒条是否被裁切。
- 静默启动期间的手动激活不能被排队隐藏操作覆盖；关闭/最小化留在托盘，真正退出时释放图标、事件和定时器。
- 托盘菜单整体宽72 DIP（含两侧各8 DIP阴影留白），检查14 DIP文字完整显示、键盘操作、菜单外点击关闭、屏幕边缘位置及释放；调整宽度时同步检查内边距，不能仅修改最小宽度。

## 五、验证与报告

- 运行适用构建、业务/UI 检查及静态检查；对职责调整涉及的状态、命令、规则和生命周期作针对性验证。
- 至少覆盖一次性与各周期、起始日限制、31日/2月29日、阴历29/30日、闰月、腊月跨年、JSON 往返/无效文件保护、提醒去重及编辑界面。
- 绑定、焦点、滚动等视图行为通过对应 UI 检查确认；不能仅凭 ViewModel 测试通过判定界面正确。离屏渲染不代表真实桌面交互、跨显示器 DPI、声音或任务栏提醒验证。
- 项目命令：`dotnet build -c Release`；`dotnet run --project Tests/CalendarChecks.csproj -c Release`。涉及发布/单实例时按影响补充 `Tests/PortableChecks.ps1` 和 `Tests/InstanceChecks.ps1 -RuntimeDirectory dist/OneSchedule`。
- 简要报告主要问题及分类、必要修改、实际删除文件、验证证据、未验证范围、尚未解决的问题和 Git 提交记录。不要把维护性偏好描述为功能错误。

## 六、Git 提交与推送

- 检查 Git 状态，保留原有未提交改动；不擅自切换或合并分支，只提交本次任务涉及的修改。
- 用户授权包含提交/推送时，在验证通过、仓库和远程条件满足后，提交并推送当前分支对应的 GitHub 远程分支，不强制推送；本 skill 明确要求执行的“验证与提交”属于该授权范围。
- 若验证失败或提交条件不满足，说明原因，不强行提交/推送。没有仓库时说明情况，不擅自初始化或配置远程。

# OneSchedule 项目代码审查与整理

先确认用户授权的范围、现有改动和行为契约。讨论阶段只读；实施阶段以用户已确认的新方案为准。不要把审查扩大为无关重写。

## 审查与修改

1. 检查职责、数据流、生命周期、异常处理和可读性。优先简单直接的实现；允许少量简单重复，仅复用有实际收益的复杂逻辑，不以行数或类数量为目标。
2. 区分正确性必修、可靠性/维护性建议、可选风格。保持本次需求未要求改变的行为；重大功能/架构调整先提出方案，已确认的变更直接实施。
3. 检查代码、调用方、测试、示例、文档之间的冲突与重复，删除本次变更淘汰的分支，不同时维护两套周期或JSON规则。
4. 仅清理确认无用的文件与本次产生的临时内容；保护资源、配置、现有日程及备份。不得把读取失败当成空列表覆盖保存。
5. 运行适用的构建、业务/UI检查与静态检查。报告实际证据及未验证范围，离屏渲染不代表真实桌面交互或声音/任务栏验证。
6. 检查Git状态并保留已有改动。仅在仓库、远程及提交条件满足且用户授权范围包含提交时提交/推送相关变更，不强推；没有仓库时说明，不擅自初始化或配置远程。

## WPF职责边界

- **Model（Models/）**：日程结构、历法、周期、数字日期及无界面依赖的规则。不引用Window或控件；显示文字与存储数值分开。
- **View（Views/、Controls/）**：XAML展示、输入、绑定、焦点、窗口交互与布局。合理的code-behind可保留，不为架构形式清空代码。
- **ViewModel**：仅在确有状态/命令协调收益时引入，不要求每个窗口创建类；不承载WPF控件实例。
- **Services/、Algorithm/**：集中持久化、日期发生判断、农历转换、提醒及系统能力。窗口通过具体服务直接协调，Model不反向依赖窗口。计时器/事件/声音等按生命周期释放。
- **入口**：App负责启动与必要对象协调。避免循环依赖，不引入无收益的MVVM框架、DI容器、事件总线、通用仓储或插件层。

## OneSchedule行为契约

- 周期为无/日/周/月/年；repeatCount包含起始日，1～999，none为1；年默认100，日/周/月默认2，缺失日期不消耗次数。所选日期是起始日，之前不发生。日/周间隔1/7个实际日。
- 月/年按所选历法匹配；不存在日期跳过，禁止自动改月末。阴历月重复包含普通月与闰月；年重复保持同月、同日、同闰月属性。
- 阴历用数字年/月/日和独立闰月标志存储，不能构造为阳历DateTime。显示年二〇二六、月正…十/冬/腊及闰月、日初十/廿一；年/月/日单位在下拉框外。
- 日历事项标记、当天列表、提醒共用同一实际发生规则；重复事件只存一条规则，编辑/删除作用于整条规则。
- 提醒按每次发生的阳历日期去重；跨午夜提前提醒记录目标发生日期。检查同日多事件、重启、保存失败及规则改变后的记录处理。
- 标准UTF-8 JSON，schemaVersion=2。对照 [JSON契约](../../data-format.md) 检查模型、解析/序列化、示例、校验、测试和README，不另写互相矛盾的格式。
- 应用只直接接受版本2；版本1仅通过明确授权的开发升级工具转换，需保留原字节备份，禁止静默迁移。旧/损坏/未知版本文件应明确拒绝，阻止后续覆盖；保留原文件与备份。
- 保持紧凑WPF DIP布局及PerMonitorV2；检查传统阴历文字、闰月、验证提示与提醒条是否被裁切。
- 托盘菜单整体宽64 DIP（含两侧各8 DIP阴影留白），检查14 DIP文字完整显示、键盘与菜单外点击关闭、屏幕边缘位置及释放；调整宽度时同步检查内边距，不能仅修改最小宽度。

## 验证与报告

至少覆盖一次性与各周期、起始日限制、31日/2月29日、阴历29/30日、闰月和腊月跨年、JSON往返/无效文件保护、提醒去重及编辑界面。

项目命令：`dotnet build -c Release`；`dotnet run --project Tests/CalendarChecks.csproj -c Release`。

报告主要问题、必要修改、实际删除文件、验证结果、未验证范围和Git提交状态；不要把维护性偏好描述为功能错误。

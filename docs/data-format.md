# 日程JSON契约（schemaVersion 2）

使用标准UTF-8 JSON，路径为exe旁的 `data/MySchedule.json`，新建/保存时自动创建目录。没有文件时只加载空列表，不自动写入；首次保存创建文件。保存先校验完整数据，写同目录临时文件，成功替换时保留 `.bak`。`data/` 目录及其中的用户数据、备份和临时文件均由 `.gitignore` 排除。已有运行目录请将 `MySchedule` 文件夹重命名为 `data`，文件名不变；程序不会自动迁移目录。

这是破坏性升级，不读取旧的数组、自定义无引号格式或旧版应用数据目录。读取失败保留文件和内存旧数据，但禁止保存及提醒写入；刷新成功后恢复。检查到加载后文件内容被外部改变也禁止覆盖，要求先刷新。应用不自动迁移数据；版本1到2仅提供下文的显式升级工具。

源目录已有的日程与备份不会再自动复制到构建/发布目录，避免将旧数据或用户数据打包分发。已有运行目录若留有版本1等旧版本，需自行备份并移走旧文件，或通过显式工具转换；应用不会自动删除或覆盖它。空文件模板见 [empty-schedules.json](examples/empty-schedules.json)，完整示例见 [schedules.json](examples/schedules.json)。

## 字段

根对象必须包含 `schemaVersion: 2` 和 `events` 数组。每条事件必须包含下列全部字段（可空字段也必须出现），未知字段拒绝读取。旧 `location` 字段不兼容：含有该字段的文件将被拒绝，程序不会转换或覆盖。

| 字段 | 类型与含义 |
|---|---|
| id | 非空GUID字符串，列表内唯一，编辑保持不变 |
| name | 非空事件名称字符串 |
| note | 备注字符串，可为 `""` |
| calendar | `"solar"` 或 `"lunar"` |
| startDate | 对应历法的 `{year, month, day, isLeapMonth}`，年月日为整数，闰月为布尔值 |
| time | 本地时间，严格 `"HH:mm"`，无秒数 |
| recurrence | `"none"`、`"daily"`、`"weekly"`、`"monthly"`、`"yearly"` |
| repeatCount | 1～999整数，包含起始日的总发生次数；none必须为1。新增/升级默认：yearly为100，daily/weekly/monthly为2 |
| reminderMinutes | 0～99整数，0为准点提醒 |
| lastRemindedOccurrenceDate | 最近已提醒那次事件的阳历日期 `"yyyy-MM-dd"`，从未提醒为 `null` |

年范围1901～2100，月1～12，日期须按所选历法实际有效。阳历的isLeapMonth必须false；阴历闰月须在该年存在。阴历二月三十以独立数字存储，不解释为阳历二月三十。界面的二〇二六、冬、闰腊、廿一等只用于显示。

## 周期与提醒

- 起始日期之前不发生；none仅一次；daily每实际日；weekly每七个实际日。
- monthly按所选历法的同一日匹配，包含每个实际阴历月（含闰月），不存在该日就跳过，不调整到月末。
- yearly按所选历法同月同日匹配，阴历还必须同一闰月属性。不满足时跳过；阳历2月29日非闰年不发生。
- repeatCount按实际有效的发生日期计数，不存在的日期不消耗次数；阴历月重复中的闰月独立计数。不随程序是否运行或是否发出提醒改变次数。到期后不再标记/提醒，但保留日程记录。
- 不预生成/存储未来的多条事件；日历标记、当天列表、提醒共用发生日期判断。编辑或删除重复事件作用于整条规则。
- 提醒保留原有三分钟补发窗口，不补发更早的错过事项；跨午夜/跨年的提前提醒记录目标发生日期。同一发生日期不重复提醒，不同事件互不抑制。
- 名称/备注修改保留提醒记录；起始日期/历法/周期/时间/提前分钟改变则重置。只改次数时，原提醒日期仍在新范围内则保留，否则清除。提醒记录写入失败时回滚并显示错误，不把未记录的事项当作已提醒。

## 显式升级版本1

先保存并关闭应用，再从项目目录运行：

```powershell
dotnet run --project Tests/CalendarChecks.csproj -c Release -- --upgrade-v1 "dist/OneSchedule/data/MySchedule.json"
```

工具先验证转换结果，再原子替换文件；原始字节保留为同目录的 `MySchedule.json.schema-v1-<id>.bak`，已有滚动 `.bak` 不覆盖。版本2再次执行只校验，不改写。工具位于开发检查项目中，不随运行程序自动执行。

所有现有事件按原起始日期计数：年100、日/周/月2、无1；可能已经到期。ID、名称、备注内容和其他数据保持不变；版本1文件也必须已使用 `note` 字段，只有落在新范围外的提醒记录清为null；含旧 `location` 的文件会被拒绝。转换不会删除事件。

## 验证

运行 `dotnet run --project Tests/CalendarChecks.csproj -c Release`，包含示例解析、JSON往返、无效数据与旧文件保护、周期及提醒测试。示例是说明材料，不随应用自动载入。


## 多文件运行目录

运行程序扫描EXE旁data目录第一层全部.json文件（忽略扩展名大小写），按文件名OrdinalIgnoreCase排序，不递归子目录，不读取.bak。没有JSON时才创建有效空白MySchedule.json。新增写入排序第一个文件；修改、删除和提醒记录写回源文件。损坏文件不覆盖，跨文件ID冲突明确报错、排除冲突事件并禁用冲突文件写入；其他文件继续读取和操作。设置保存在EXE旁OneSchedule.settings.json，不属于日程数据。

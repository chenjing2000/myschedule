## 兼容性检查与必要调整

- 核对 [.NET 9](https://learn.microsoft.com/en-us/dotnet/core/compatibility/9.0)、[.NET 10](https://learn.microsoft.com/en-us/dotnet/core/compatibility/10) 兼容性说明。应用没有 BinaryFormatter 或自定义原生依赖；现有 P/Invoke 使用 Windows 系统库，发布实例检查覆盖相应托盘/窗口路径。
- WinForms 的 DPI 分析诊断现为 WFO0003。项目由 WPF manifest 声明 PerMonitorV2，WinForms 仅用于 NotifyIcon，因此保留 manifest 并将重复、失效的 WFAC010 抑制替换为单个 WFO0003；未广泛关闭分析器。[微软诊断说明](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/compiler-messages/wfo0003)
- 原缺失运行时检查依赖机器没有安装恰好匹配的基础补丁。改用隔离的 runtime root，复制 hostfxr 和可用的 .NET 8 运行时，确认 EXE 必须获得 .NET 10 才能启动；不卸载或修改本机运行时。
- 原实例脚本跨进程直接 ShowWindow 最小化时，在旧 .NET 8 EXE 和新 .NET 10 DLL 上均出现“最小化但原生可见”的状态。改发标题栏按钮对应的 WM_SYSCOMMAND/SC_MINIMIZE，让拥有窗口的 UI 线程处理真实用户命令后，同一断言通过；无产品代码变更，也不宣称修复所有外部 ShowWindow 调用情形。

## 验证证据

1. 新 RuntimeChecks 在 .NET 8 基线上以 actual 8.0.30 失败；升级后确认运行时为 10.0.11，应用和测试两个程序集的 TargetFrameworkAttribute 均为 .NETCoreApp,Version=v10.0。
2. Release 构建：0 警告、0 错误。两个生成的 runtimeconfig 均要求 Microsoft.NETCore.App/Microsoft.WindowsDesktop.App 10.0.0，无跨主版本 RollForward 配置。
3. 完整 CalendarChecks 通过：85 项事件检查、52 项日历检查、2400 个月网格，以及既有 JSON/存储安全、数字输入、下拉框、滚动条、弹窗布局、设置及托盘检查。
4. 新 PortableChecks 在旧 .NET 8 发布 EXE 上失败：隔离目录中的 .NET 8 能使旧程序启动，因此不符合“缺少 .NET 10 应拒绝启动”的要求。新 .NET 10 EXE 则通过：独立 EXE 首次运行、含空格路径、data/settings 初始化及缺失 .NET 10 提示。
5. 实例测试通过六组：已有窗口恢复/激活、关闭隐藏与重开、嵌套模态恢复、三轮快速启动竞争、静默启动后手动唤醒、启动期间提前激活。先验证 DLL 版本，再执行 `Tests/InstanceChecks.ps1 -RuntimeDirectory dist/OneSchedule` 验证最终 EXE。
6. 发布前后逐一比较 data 内全部现存文件及 settings 的 SHA-256，内容相同。发布脚本仅替换应用二进制；没有转换或重写用户数据。

主要命令：`dotnet build -c Release`、`dotnet run --project Tests/CalendarChecks.csproj -c Release`、`Publish.ps1`、`Tests/PortableChecks.ps1`、`Tests/InstanceChecks.ps1 -RuntimeDirectory dist/OneSchedule`。

# OneSchedule.Wpf v0.2.0

这是 OneSchedule 的第一版 WPF 重构程序。

## 本版目标

- 完全移除 WinForms 主界面与 GDI+ 手工日期绘制。
- 日历每格阳历在上、农历在下；今天的两行文字共同显示在蓝色圆形内。
- 日历七列等宽、固定六行；切换月份时保持网格稳定。
- 不再使用 `UiScale`、屏幕分辨率经验缩放或大 `Viewbox`。
- 使用 WPF DIP + `PerMonitorV2`，支持窗口自由缩放和不同 DPI 显示器。
- 支持阳历/阴历、闰月、无/日/周/月/年五种周期与提前提醒；新版本采用标准JSON，不兼容旧格式。
- 支持查看、新增、编辑、删除日程；双击事项可编辑。
- 有事项的日期右下角显示周期颜色三角：无 #A477E8、日 #39A9EB、周 #41C984、月 #F5AC3D、年 #F45D75。同日多条事项采用最早时间的事项颜色，同一时间保留原有顺序；鼠标停留仍显示全部事项。
- 主窗口默认400×460 DIP，最小380×440 DIP；日期、月份、年份三级视图共用内容区域。

## 编译环境

- Windows 10 / 11
- .NET 8 SDK
- Visual Studio 2022/2026（勾选“.NET 桌面开发”）或命令行

## 编译运行

双击 `build-release.bat` 发布程序，再双击 `run.bat` 直接启动：

```powershell
.\build-release.bat
.\run.bat
```

发布批处理调用 `Publish.ps1`，最终入口固定为 `dist/OneSchedule/OneSchedule.exe`。发布成功后删除SDK必需的两个临时apphost，不保留其它项目EXE。`run.bat` 不编译；未发布时提示先运行发布脚本。

普通开发构建及测试默认禁用apphost，只生成DLL，可通过 `dotnet run` / `dotnet run --project Tests/CalendarChecks.csproj` 启动。直接使用 `dotnet publish` 时，若需要最终EXE，必须显式传入 `-p:UseAppHost=true`；推荐统一使用发布脚本，避免遗留临时EXE。

用户日程位于最终EXE旁的 `data/` 文件夹。DLL、deps/runtimeconfig等运行文件仍需保留。同一用户的同一桌面会话只运行一个实例；再次启动会恢复并激活已有窗口或当前弹窗。

## 数据文件

程序使用：

`data\MySchedule.json`

运行时路径相对于exe所在目录。采用UTF-8标准JSON（schemaVersion=2），保存时保留 `.bak`。`data/` 中的用户数据、备份和临时文件均由 `.gitignore` 排除。已有运行目录请将 `MySchedule` 文件夹重命名为 `data`，文件名不变；程序不会自动迁移目录。详见 [数据契约](docs/data-format.md) 和 [完整示例](docs/examples/schedules.json)。

应用仅直接读取版本2，读取失败时禁止保存覆盖。版本1可使用数据契约中列出的显式升级命令，转换前备份原文件；不自动升级其他旧格式。源目录原日程和备份保持不变，不再复制到构建/发布目录。已有运行目录若留有旧文件，请先自行备份并移走，或按新格式自行重建；程序不会自动删除它。

## 弹窗外观与位置

- 当天事项窗口与新增/编辑窗口使用相同字体、14号常规字重；移除日期下重复的“今日日程”标签。
- 当天事项窗口打开时与主窗口同宽、左对齐、垂直居中；新增/编辑窗口打开时与当天事项窗口同宽、左对齐、垂直居中。
- 宽度取父窗口打开当时的实际宽度，支持主窗口缩放后的宽度；通过相同宽度配合WPF CenterOwner实现，不额外计算屏幕坐标。

## 新增与编辑日程

- 新增和编辑共用同一窗口与【取消】【保存】操作；删除日程统一在【今日日程】窗口中完成。
- 新增/编辑窗口默认宽400 DIP、高度按内容收紧，14号常规字体；打开时匹配父窗口实际宽度。首行为“类型”阳历/阴历切换按钮及“周期”无/日/周/月/年，以及“重复…次”输入框。
- 日期只有一行，年/月/日单位在框外。切换历法转换同一实际日期；阴历显示二〇二六年、正…十/冬/腊月（含闰月）、初十/廿一等传统日名。
- 次数包含起始日这一次，有效范围1～999，只接受最多三位数字。年默认100次，日/周/月默认2次；无周期时次数为1且输入框禁用。切换周期填入对应默认值，打开编辑保留已存次数。
- 达到总次数后停止后续日期标记和提醒，但不自动删除记录；不存在的日期不消耗次数。
- 所选日期是起始日期，之前不发生。日/周按实际1/7天重复，月/年按所选历法匹配；月重复包含闰月，缺失日期跳过，不顺延到月末。
- 阳历年重复的2月29日在非闰年跳过；阴历年重复还需匹配同一闰月属性。重复事件只保存一条规则，编辑/删除作用于整条规则。
- 新增日程的提前提醒默认为0分钟；编辑时保留原值。提醒与重复次数数字水平居中，两种数字框使用较小内部留白，42 DIP宽度完整显示三位数及末尾光标；点击提前提醒输入框时光标置于数字末尾，不自动全选。事件与地点框使用单一的小内边距。
- 周期、月、日、时、分下拉框及提醒/重复输入框统一42 DIP宽度；历法按钮48 DIP，五个底部操作按钮统一60 DIP；年份72 DIP，足以显示四字阴历年份。所有下拉框和选项文字居中，去掉箭头及其占位，整框可点击展开。圆角、窗口同色背景配合细边框，以及悬停/焦点/展开时的明暗变化区分状态。
- 日期与时间的单字标签区域统一22 DIP，“周期”“重复”标签区域统一36 DIP；长输入框宽度取整。提醒行到操作按钮的空白缩至16 DIP，校验错误出现时窗口自动增高。
- 下拉列表使用像素滚动，240 DIP视口约显示八行；滚动到底时紧贴最后一个真实选项，不再留出近一行空白。仅在需要时显示6 DIP细滚动条，无两端箭头，保留滑块拖动、轨道翻页、滚轮和键盘操作；悬停或拖动时滑块加深。
- 【今日日程】列表中双击事件所在行可编辑；双击行外空白处新增当前查看日期的空白日程，双击滚动条不打开弹窗。
- 时间、事件、地点、0～99分钟提前提醒和底部操作保留。名称/地点修改不会重置提醒；规则/日期/时间/提醒分钟变化会重置。
- 提醒按目标发生日期去重，跨午夜提前提醒可正确记录；保存提醒状态失败会显示错误。保留原有三分钟补发窗口。

## DPI / 跨电脑适配原则

- Manifest 声明 `PerMonitorV2`。
- UI 尺寸均使用 WPF DIP。
- 不读取屏幕分辨率计算额外缩放因子。
- 日历 7 列始终星号等宽。
- 日期格使用固定直径44 DIP的圆形容器，阳历/农历两行居中；空间不足时内容区出现滚动条，避免压扁圆形。
- 主窗口允许缩放，并设置合理的 `MinWidth` / `MinHeight`。

## 日历操作

- 顶部始终显示今天的阳历、星期和完整农历日期，跨午夜自动更新。
- 单击日期只选中，双击左键才打开当天日程；切换月份、刷新日程后仍记住选中日期。
- 今天保持实心圆；选中的其它日期显示强调色圆框和文字；悬停仅显示圆形背景，提醒闪烁时保持文字对比度。
- 点击“2026年10月”进入月份视图（四列三行），再点击“2026年”进入年份视图（四列四行）。
- 点击年份进入对应月份视图，点击月份返回日期视图；淡化的相邻有效年份也可点击。
- 上/下箭头、滚轮向上/向下分别浏览更早/更晚的月份、年份或十年区间。
- 滚动只改变浏览范围，不自动改变已选年份高亮；高精度滚轮累计120单位切换一次。
- Esc从年份返回月份、从月份返回日期；“今天”在任意层级返回今天所在月份并选中今天。
- 年份范围1901～2100，越界的年份和日期补位格不可选。
- 右上角“↻”重新读取日程；正常时不显示底部说明，读取错误明确显示。
- 提醒条支持换行；三个层级均保留提醒闪烁。提醒/错误占用空间时可拖动内容区滚动条查看完整网格，滚轮仍用于日历翻页。

无第三方测试包的STA WPF检查：

```powershell
dotnet run --project Tests/CalendarChecks.csproj
```

单实例真实进程检查使用隔离的运行副本，不读取用户日程：

## 历史版本记录

以下为旧版本变更记录；当前数据格式以以上数据契约为准。

### v0.1.1 修复

- 显式加入 `System.IO`，修复 Path/File/Directory/FileStream/BinaryWriter 无法识别。
- 修正 Lunar.cs 与 ScheduleJson.cs 的 nullable 编译警告。


## v0.2.0-r1 第一轮结构重构

- 合并颜色与控件样式为 `Resources/Theme.xaml`。
- Calendar 小型辅助类型并入 `CalendarView.xaml.cs`。
- 声音提醒、任务栏闪烁归并到 `Services/ReminderService.cs`。
- 多个版本日志合并为单一 `CHANGELOG.md`。
- 本轮不改变日程数据格式与界面行为。

## v0.2.0-r2 第二轮重构

- 日程加载、查询、新增、编辑、删除、保存和 ID 分配统一由 `ScheduleService` 管理。
- 日程业务与持久化集中在 `Services/ScheduleService.cs`，避免多个窗口重复操作 List 和文件。
- 提醒服务直接读取统一日程服务，不再维护第二份日程引用。
- 删除过度设计的 `MainViewModel`，主窗口只保留少量简单显示状态。
- 本轮仍不改变 `MySchedule.json` 数据格式和已确认的 UI 行为。


## v0.2.0-r3 第三轮重构

- Calendar 日期格改为 `DataTemplate`，删除独立 `DateCellControl`。
- 今天、周末、非本月、事项标记和提醒闪烁统一由 Calendar 模块控制。

## v0.2.0-r4 第四轮重构

- 合并新增/编辑日程的初始化流程。
- 统一年月日、阴历/阳历、闰月和日期有效性处理。

## v0.2.0-r5 第五轮重构

- `EventType` 内部改为 `ScheduleType` 枚举，消除业务代码中的字符串状态比较。
- 时间内部统一使用 `TimeOnly?`，只在 UI 与 JSON 边界格式化为 `HH:mm`。
- 排序、提醒时间计算和编辑比较直接使用强类型时间。
- `MySchedule.json` 的字段名和值保持兼容。
